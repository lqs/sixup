# sixup: IPv6 ルーティングを全自動で設定

<a href="README.md" lang="en">English</a> | <a href="README.zh.md" lang="zh-Hans">简体中文</a> | <strong>日本語</strong>

[![CI](https://github.com/lqs/sixup/actions/workflows/ci.yml/badge.svg)](https://github.com/lqs/sixup/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

かつて Linux で IPv6 ルーティングを組むには、いくつものプログラムが必要でした。
プレフィックス取得に `odhcp6c`、RA の送信に `radvd`、DHCPv6 に `odhcpd`、代理応答に
`ndppd`、さらにその間でパラメータを受け渡し、必要に応じて再起動をかけるスクリプト。

sixup はこれを 1 つのプログラムで行います。各段階の状態とパラメータはプロセスの内部で
受け渡され、スクリプトを介しません。回線がプレフィックスを変更すれば、インターフェイスの
アドレス、RA の内容、DHCPv6 リース、代理応答のエントリ、トンネルのエンドポイントが
同じ一つのイベントから更新され、手作業も再起動も必要ありません。

## 機能

- IPv6 ルーターに必要な機能を一通り内蔵し、他のデーモンの設定は不要
- 家庭用ルーターについての RFC に基づいて設計し、全体は RFC 7084、ファイアウォールは RFC 6092 に従う。[各要件と対応状況](docs/standards.md)を一覧にしている
- プレフィックスの取得方式（DHCPv6-PD / RA）を自動で判別し、内蔵の RA と DHCPv6 サーバーがアドレスと設定を配布
- 事業者がプレフィックスを変更すると、アドレス、RA、リース、代理応答エントリ、トンネルのエンドポイントが追従
- 上流が /64 のみなら RFC 7278 に従って LAN と共有し、ブロードキャスト型の WAN では NDP 代理応答も有効化、より短いプレフィックスなら各セグメントへ分割
- 下流のルーターにプレフィックスを委任し、sixup の下にさらに sixup を置ける
- 要求されていない IPv6 の着信を LAN に入れず、プログラムは PCP でポートを開ける
- 必要に応じて DS-Lite、MAP-E、IPIP6 のトンネルを構築し、MAP-E では割り当てられたポートセットを維持
- 単一の静的バイナリで 6 MiB 未満。外部コマンドにもシステムサービスにも依存しない

## クイックスタート

> [!WARNING]
> <span lang="ja">本プロジェクトは開発中で、まだリリースしていません。実回線で一度も
> 動かしていない部分があり、まったく動かない可能性があります。オプションも随時変わります。</span>

<div lang="ja">

[Releases ページ](https://github.com/lqs/sixup/releases) から、ディストリビューションに合った
パッケージ（`.deb`、`.rpm`、`.apk`、Arch Linux の `.pkg.tar.zst`）か静的バイナリを入手して
ください。正式版はまだなく、`dev` プレリリースのみです。

回線が何を提供しているかを、システムを変更せずに確認する：

```sh
sudo sixup -wan eth0 -dry-run
```

WAN インターフェイスからプレフィックスを取得し、LAN インターフェイスを構成する：

```sh
sudo sixup -wan eth0 -lan eth1
```

プレフィックスは回線が対応している方式で取得します。他のオプションは必要ありません。

一つの委任プレフィックスを複数の LAN セグメントへ分けるときは、インターフェイスごとに
サブネット番号を指定します：

```sh
sudo sixup -wan eth0 -lan eth1:0 -lan eth2:1
```

注意：/64 が一つでは LAN セグメント一つ分にしかなりません。委任のない回線では、サブ
ネット番号 0 のセグメントがそのプレフィックスを受け取り、残りには割り当てられません。
セグメント同士で通信する必要があれば `-lan-ula auto` で ULA を配布してください。

注意：MAP-E 回線では、送信元ポートが回線に割り当てられたポートセットの内側に収まって
いなければ、戻りの通信が届きません。この nftables ルールは sixup が維持します。書き込む
のは `inet sixup` テーブルだけで、終了時に自動で削除します。自分で書く場合は `-tunnel-nat off`
を指定してください。

複数の LAN セグメント、固定アドレス、DNS サーバーの指定、NAT64 など、ほかの用途については
[設定レシピ](docs/recipes.ja.md)を参照してください。sixup が従う RFC と、項目ごとの対応状況や未対応の点は [Standards](docs/standards.md)
（英語）にまとめています。

## オプション

</div>

> [!WARNING]
> <span lang="ja">まだリリースしていないため、オプションは予告なく名前が変わったり削除されたりすることがあります。</span>

<div lang="ja">

`sixup -h` は全オプションを以下のグループで一覧表示します。

- 真偽値のオプションは `=false` で無効にします。例：`-wan-ra=false`。
- 時間は Go の書式で指定します：`30s`、`10m`、`1h30m`。
- 繰り返し指定できるオプションは、値ごとに一回ずつ書きます：`-lan eth1 -lan eth2`。

### インターフェイスとプレフィックス

| オプション | 既定値 | 説明 |
|---|---|---|
| `-wan` | | WAN インターフェイス。必須。 |
| `-lan` | | LAN インターフェイス。繰り返し指定でき、書式は `名前[:サブネット番号]`。サブネット番号は 10 進数で、委任プレフィックスのうちどの /64 をこのインターフェイスに割り当てるかを決めます。省略すると、書いた順に 0、1、2 となります。LAN インターフェイスが複数あるときは委任プレフィックスが必要です。 |
| `-lan-ula` | | グローバルプレフィックスと並べて広告する ULA プレフィックス。`auto` はランダムな /48 を生成して状態ディレクトリに保存し、`fd12:3456:789a::/48` のようなプレフィックスはそのまま使います。複数はカンマ区切り。 |
| `-lan-iid` | | 各 LAN プレフィックス上のルーター自身のアドレスのインターフェイス識別子。カンマ区切りで一項目につき一アドレス、書式は `-wan-iid` と同じ。空なら RFC 7217 の安定アドレスを一つ。 |
| `-lan-deprecate-hold` | `1h30m` | 回線が取り下げたプレフィックスを、優先寿命と有効寿命をともに 0 にして広告し続ける時間。クライアントはこれでそのプレフィックスを捨てます（RFC 9096）。LAN のプレフィックスは状態ディレクトリに記録されるので、再起動の前に広告していて回線が再び割り当てなかったプレフィックスも同じように広告します。 |

### WAN 側：DHCPv6 クライアント

| オプション | 既定値 | 説明 |
|---|---|---|
| `-dhcp6c-mode` | `auto` | `auto` は上流 RA の M、O フラグに従い、`on` は常にクライアントを動かし、`off` は動かしません。 |
| `-dhcp6c-pd-len` | `56` | 委任プレフィックス（IA_PD）を要求するときに示すプレフィックス長。実際に委任される長さはサーバーが決めます。サーバーがこの指定を拒否した場合、sixup は指定なしでもう一度要求します。`0` なら要求しません。 |
| `-dhcp6c-ia-na` | `true` | WAN インターフェイス自身のアドレス（IA_NA）も要求します。 |
| `-dhcp6c-pd-grace` | `10s` | 起動後に委任プレフィックスを待つ最長時間。PD が成功するか拒否されるとすぐに終わり、通常は数秒です。その間 RA のプレフィックスは LAN に渡さないので、後から取り下げる必要がありません。RA が M か O を立てている場合は、WAN もまだそのプレフィックスでアドレスを持ちません。LAN がこの /64 を共有するかどうかでアドレスのプレフィックス長が決まるためです。 |
| `-dhcp6c-release` | `false` | 終了時に RELEASE を送り、プレフィックスとアドレスを返却します。既定では無効です。DUID を保存しているので、再起動後も同じプレフィックスを更新できます。ドライランでは常に返却します。 |

### WAN 側：上流 RA とアドレス

| オプション | 既定値 | 説明 |
|---|---|---|
| `-wan-ra` | `true` | 上流の RA を二つ目のプレフィックス取得元として受信し、それに基づいてデフォルトルートを維持します。 |
| `-wan-slaac` | `true` | A フラグ付きの RA プレフィックスについて、WAN インターフェイスに SLAAC アドレスを設定します。 |
| `-wan-iid` | | WAN インターフェイスの静的 SLAAC アドレスのインターフェイス識別子。カンマ区切りで一項目につき一アドレス。各項目は、RFC 7217 の安定アドレスなら `stable` または空、MAC アドレスから作るなら `eui64`、固定するなら `::1` や `::1111:2222:3333:4444` のようなサフィックス。最初のものを WAN アドレスとして報告します。 |
| `-wan-tempaddr` | `false` | WAN インターフェイスでも一時アドレスをローテーションします。設定は `-tempaddr-*` に従います。 |
| `-wan-prefer` | `pd` | 委任プレフィックスと RA プレフィックスの両方があるとき、どちらを使うか：`pd` または `ra`。 |
| `-wan-prefix` | （空） | 上流がこのルーターへルーティングしているが、RA でも DHCPv6-PD でも知らされないプレフィックス。契約により回線へ静的にルーティングされる固定プレフィックスや VPS の /64 などで、複数はカンマ区切り。指定すると DHCPv6 クライアントは DNS などの設定だけを要求します。/64 は WAN リンクの on-link プレフィックスとして扱い、LAN と共有します（RFC 7278）。それより短いものは委任されたプレフィックスとして扱います。 |
| `-wan-shared64` | `lan` | 上流から /64 が一つしか得られないときの配置。`lan`：/64 を LAN に置き、WAN リンク上のホストには /128 ルートを使います（RFC 7278）。`wan`：/64 を WAN 側に残し、LAN のホストごとに /128 ルートを使います。`split`：両側とも /128 ルートで、ルーター自身はまだ学習していないホストに届きません。/128 ルートは NDP 代理応答がホストを見つけたときに自動で追加します。 |

### LAN 側：RA の広告

| オプション | 既定値 | 説明 |
|---|---|---|
| `-ra-min` | `3m20s` | 定期 RA の最小送信間隔（MinRtrAdvInterval）。 |
| `-ra-max` | `10m` | 定期 RA の最大送信間隔（MaxRtrAdvInterval）。 |
| `-ra-lifetime` | `45m` | RA に載せるルーター寿命（RFC 9096）。WAN にデフォルトルーターがない間は 0。 |
| `-ra-slaac` | `true` | RA のプレフィックスに A フラグを立て、ホストが SLAAC でアドレスを作れるようにします。`-dhcp6s-mode stateful` と組み合わせて無効にすると、アドレスは DHCPv6 だけで配布します。 |
| `-ra-onlink` | `true` | RA のプレフィックスに L フラグを立て、ホスト同士が直接通信できるようにします。無効にすると、ホストの通信はすべてルーターを経由します。 |
| `-ra-mtu` | `0` | RA で広告する MTU。`0` のときは、WAN 経路の MTU が LAN インターフェイスの MTU より小さければそれを広告します。WAN 経路の MTU は上流 RA または WAN インターフェイスから取ります。これで PPPoE の 1492 なども経路 MTU 探索に頼らずに済みます。 |
| `-ra-dns` | `upstream` | LAN に通知する DNS サーバー。RA と DHCPv6 サーバーの両方で使います。`off` なら通知しません。それ以外は次の項目を順にカンマ区切りで並べます：`upstream`（上流から配布されたサーバー）、`self`（この LAN 上のルーター自身のアドレス。ULA があれば ULA を使うので、プレフィックスが変わっても有効です）、IPv6 アドレス。例：`self,upstream`。 |
| `-ra-pref64` | `auto` | RA で広告する NAT64 プレフィックス（RFC 8781）。`auto` はこのルーター自身の NAT64 が変換している間はそのプレフィックス `-nat64-prefix` を、それ以外は上流 RA の値を広告します。`off` は広告しません。プレフィックスを書くと、別の場所にある NAT64 のものとしてそれを広告します。`-nat64` とは併用できません。 |
| `-ra-route` | | ルート情報オプション（Route Information）として広告するプレフィックス。繰り返し指定可。 |

### LAN 側：DHCPv6 サーバー

| オプション | 既定値 | 説明 |
|---|---|---|
| `-dhcp6s-mode` | `off` | `stateless` はアドレスを割り当てず DNS などのオプションを返し、`stateful` はアドレスも割り当てます。どちらも下流のルーターにプレフィックスを委任します（`-dhcp6s-pd-len`）。`off` はサーバーを動かしません。RA のフラグもこれに合わせます。 |
| `-dhcp6s-pool` | `1000-ffff` | 割り当てに使うインターフェイス識別子の範囲。16 進数で、下位 64 ビットを指します。 |
| `-dhcp6s-static` | | 固定割り当て。繰り返し指定可：`mac=<MAC>,addr=::100` または `duid=<16 進数>,addr=2001:db8::5`。 |
| `-dhcp6s-lease-preferred` | `45m` | 割り当てたアドレスと委任したプレフィックスの優先寿命。上流の残り時間を超えません。既定値は RFC 9096 が推奨する上限です。 |
| `-dhcp6s-lease-valid` | `90m` | 割り当てたアドレスと委任したプレフィックスの有効寿命。同じく上流の残り時間で制限します。 |
| `-dhcp6s-pd-len` | `60` | 下流のルーターに委任する最大のプレフィックスを、プレフィックス長で指定します。より長いプレフィックスを求められればそのとおりに、より短いものを求められればこの長さで委任し、空きが足りなければさらに長くします。委任するプレフィックスは上流から委任されたものから LAN のサブネットを避けて切り出し、どちらのサーバーモードでも使えます。`0` で下流への委任を無効にします。 |

### NDP 代理応答

| オプション | 既定値 | 説明 |
|---|---|---|
| `-ndproxy-mode` | `auto` | `auto` は LAN の /64 がブロードキャスト型 WAN の on-link /64 でもあるとき `forward` を有効にし、それ以外では無効にします。委任されたプレフィックスや point-to-point の WAN には代理応答は要りません。`forward` は応答する前に反対側を探索し、これを双方向に行うので、WAN リンク上のホストと LAN のホストの間でも通信できます。`prefix` は LAN プレフィックス内のアドレスに対する WAN 側からの要請に、探索せずにすべて応答します。`static` は `-ndproxy-static` の項目をカーネルの代理応答テーブルに登録するだけです。`off` は代理応答を無効にします。 |
| `-ndproxy-static` | | `static` モードで代理応答するアドレスまたはプレフィックス。繰り返し指定可。 |
| `-ndproxy-exclude` | | 代理応答しないプレフィックス。繰り返し指定可。 |
| `-ndproxy-ttl` | `30s` | 学習した代理応答エントリの存続時間。 |

### 自身のアドレスのローテーション

このグループは LAN 上のルーター自身のアドレスを制御します。`-wan-tempaddr` を付けると WAN 側も対象になります。

| オプション | 既定値 | 説明 |
|---|---|---|
| `-tempaddr-mode` | `off` | `temporary` と `both` は静的アドレスに加えてローテーションする一時アドレス（RFC 8981）を置き、`off` と `stable` は静的アドレスだけにします。 |
| `-tempaddr-regen` | `1h` | 新しい一時アドレスを作る間隔。 |
| `-tempaddr-preferred` | `1h` | 一時アドレスの優先寿命。 |
| `-tempaddr-valid` | `24h` | 一時アドレスの有効寿命の上限。使用中のアドレスはこの上限まで残し、使われなくなったものは早めに削除します。 |
| `-tempaddr-max` | `8` | 同時に持つ一時アドレスの上限数。 |
| `-tempaddr-desync` | `10m` | ローテーションごとに加えるランダムなずれの上限。 |
| `-tempaddr-skip-dad` | `false` | 重複アドレス検出を省略します。衝突がないと分かっているリンクでだけ使ってください。 |
| `-tempaddr-drain-grace` | `5s` | アドレスが使われなくなったと判断するための二回の確認の間隔。 |

### トンネル

| オプション | 既定値 | 説明 |
|---|---|---|
| `-tunnel-dev` | `sixup-ipv4` | IPv4-in-IPv6 トンネルデバイスの名前。トンネルのパラメータが揃うと、sixup がこのデバイスを作成または更新し、有効にして IPv4 アドレスを設定します。空ならデバイスを作りません。 |
| `-tunnel-mtu` | `0` | トンネルデバイスの MTU。`0` は WAN インターフェイスの MTU から 40 を引いた値です。 |
| `-tunnel-route4-metric` | `4096` | トンネル経由の IPv4 デフォルトルートのメトリック。わざと大きくしてあり、既存の IPv4 デフォルトルートが優先され、それがないときだけトンネルが引き継ぎます。`0` ならルートを追加しません。 |
| `-tunnel-nat` | `auto` | トンネルから出る通信のために nftables のテーブル `inet sixup` を維持します。`auto` は、MAP-E では必須のポート制限付き送信元 NAT（RFC 7597）を、専用の IPv4 アドレスを持つ回線では通常の送信元 NAT を設定し、事業者側で変換する DS-Lite では設定しません。いずれの場合も TCP MSS をトンネル MTU に合わせて制限します。`off` はルールを書きません。テーブルの外には一切触れず、終了時にテーブルを削除します。 |
| `-tunnel-mape-rules` | `true` | DHCPv6 に MAP-E オプションがないとき、日本の IPoE 事業者（v6プラス、BIGLOBE、OCN、NURO）のルール表を使い、委任プレフィックスから MAP-E のパラメータを求めます。 |
| `-tunnel-capture` | `true` | DHCPv6 にトンネルのオプションがないとき、トンネルの通信をキャプチャしてパラメータを特定します。`-dhcp6c-mode` が `off` でないことが必要で、ドライランでは行いません。 |
| `-tunnel-capture-max` | `2m` | キャプチャで待つ時間。最初のトンネルパケットで終わり、届かなければ諦めて、プレフィックスかアドレスが変わったときに再試行します。 |

### NAT64

| オプション | 既定値 | 説明 |
|---|---|---|
| `-nat64` | `off` | `jool` は [Jool](https://jool.mx) カーネルモジュール（4.1 以降、`modprobe jool` で読み込み）で NAT64 を設定します。Jool は専用のネットワーク名前空間で動き、veth `sixup-nat64` でつながります。`-nat64-prefix` を変換し、LAN からもこのルーター自身からも使えます。名前空間を作り、RA でこのプレフィックスを広告する（`-ra-pref64 off` なら広告しない）のは、モジュールが読み込まれている間だけです。sixup は毎分確認するので、モジュールの読み込み、取り外し、再読み込みに再起動は要りません。変換後の IPv4 はこのホストの IPv4 ルートで出ていきます。トンネル経由なら上記の送信元 NAT を通るので MAP-E 回線のポートを割り当てるのは一か所だけで、トンネルがなければ設定済みの別の IPv4 出口を使います。ファイアウォールでは `sixup-nat64` を通る通信を許可してください。転送される LAN の通信だけでなく、このルーター自身あての応答もこのインターフェイスから届きます。名前空間は sixup の終了とともに消えます。`off` は設定しません。DNS64 は含まれず、お好みのリゾルバーに任せます。 |
| `-nat64-prefix` | `64:ff9b::/96` | NAT64 が変換するプレフィックス（RFC 6052）。長さは 32、40、48、56、64、96 のいずれか。NAT64 でプライベート IPv4 アドレスに届くには、ULA の `fd00:64::/96` のようなネットワーク固有プレフィックスが必要です。委任プレフィックスから切り出したものは、それとともに変わるので向きません。 |
| `-jool-ipv4` | `192.168.255.254/31` | この名前空間と Jool の名前空間の間の IPv4 /31。小さいほうのアドレスがこちら側のゲートウェイ、大きいほうが Jool の pool4 です。このホストの既存のアドレスやルートと重なる場合、sixup は起動しません。 |

### 要求されていない着信

| オプション | 既定値 | 説明 |
|---|---|---|
| `-unsolicited` | `request` | WAN から LAN への要求されていない通信（RFC 6092）の扱い。LAN の通信への応答ではなく、インターネット側から始まる接続のことです。`request` は WAN から来る IPv6 を RFC 6092 に従って遮断します。LAN が始めた通信、RFC 4890 が求める ICMPv6、IPsec（AH、ESP、IKE）と HIP、5 分以内に外へ送信したエンドポイントあての通信（エンドポイント非依存フィルタリング。Tailscale などの P2P プログラムはこれで動き続けます）、LAN のプログラムが PCP（RFC 6887、UDP 5351）で開けたポートを通し、それ以外は破棄します。下流のルーターに委任したプレフィックスは、そのルーター自身のファイアウォールに任せます。`deny` は同じ遮断で PCP を提供しません。`allow` は要求されていない通信も通し、PCP は IPv6 ホストにすでに到達できると答えます。どのモードでも、ULA を送信元または宛先とする通信は WAN を通らず、LAN は自分のプレフィックスと委任したプレフィックスからだけ外へ送信でき、それ以外の送信元には ICMPv6 code 5 を返します。WAN から届くのはこれらのプレフィックスあてだけで、回線がプレフィックスを割り当てる前は何も通さず、これらのプレフィックスを送信元とする通信も通しません（RFC 7084 ULA-4、S-2、L-14、G-3、RFC 6092 REC-6）。遮断するのは転送する通信だけで、ルールは `inet sixup-filter` テーブルにあります。ルーター自身のサービスは利用者が管理してください。`allow` と `request` では、sixup がトンネルの NAT を行っている間（`-tunnel-nat auto`）、PCP はトンネルの IPv4 の TCP または UDP ポートを LAN のホストに転送し（NAT-PMP（RFC 6886）しか使えないプログラムは NAT-PMP でも要求できます）、ホストがそのポートから送る通信も同じ外部ポートから出します。ほかの LAN のホストも公開アドレスでそこに届きます。外部ポートは 1024 以上で、ルーター自身が待ち受けているポートは使わず、MAP-E 回線では回線のポートセットから割り当てます。DS-Lite 回線ではマッピングできません。1 台のホストが持てるマッピングは 16 個までです。マッピングはメモリ上にだけあり、起動時とトンネルのアドレスが変わったときに、以前のマッピングが失われたことを LAN に通知します。 |
| `-source-filter` | `true` | LAN から WAN へは、LAN 自身のプレフィックスとそこから委任したプレフィックスを送信元とする通信だけを通し、それ以外の送信元には ICMPv6 code 5 を返します（BCP 38、RFC 7084 S-2 と L-14）。WAN から届くのもこれらのプレフィックスあてだけです。ほかの方法で LAN にルーティングされているプレフィックスがある場合は無効にしてください。 |
