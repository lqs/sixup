# sixup: IPv6 ルーティングを全自動で設定

<a href="README.md" lang="en">English</a> | <a href="README.zh.md" lang="zh-Hans">简体中文</a> | <strong>日本語</strong>

[![CI](https://github.com/lqs/sixup/actions/workflows/ci.yml/badge.svg)](https://github.com/lqs/sixup/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

かつて Linux で IPv6 ルーティングを組むには、いくつものプログラムが必要でした。
プレフィックス取得に `odhcp6c`、RA の送信に `radvd`、DHCPv6 に `odhcpd`、代理応答に
`ndppd`、さらにその間でパラメータを受け渡し、必要に応じて再起動をかけるスクリプト。

sixup はこれを 1 つのプログラムで行います。各段階の状態とパラメータはプロセスの内部で
受け渡され、スクリプトを介しません。回線がプレフィックスを変更すれば、インターフェイスの
アドレス、RA の内容、DHCPv6 リース、代理応答のエントリ、トンネルのエンドポイントが
同じ一つのイベントから更新され、手作業も再起動も必要ありません。

## 機能

- IPv6 ルーターに必要な機能を一通り内蔵し、他のデーモンの設定は不要
- プレフィックスの取得方式（DHCPv6-PD / RA）を自動で判別し、内蔵の RA と DHCPv6 サーバーがアドレスと設定を配布
- 事業者がプレフィックスを変更すると、アドレス、RA、リース、代理応答エントリ、トンネルのエンドポイントが追従
- 上流が /64 のみなら RFC 7278 に従って LAN と共有し NDP 代理応答を有効化、より短いプレフィックスなら各セグメントへ分割
- 必要に応じて DS-Lite、MAP-E、IPIP6 のトンネルを構築し、MAP-E では割り当てられたポートセットを維持
- 単一の静的バイナリで 5 MiB 未満。外部コマンドにもシステムサービスにも依存しない

回線が何を提供しているかを、システムを変更せずに確認する：

```sh
sudo sixup -wan eth0 -dry-run
```

WAN インターフェイスからプレフィックスを取得し、LAN インターフェイスを構成する：

```sh
sudo sixup -wan eth0 -lan eth1
```

プレフィックスは回線が対応している方式で取得します。他のオプションは必要ありません。

一つの委任プレフィックスを複数の LAN セグメントへ分けるときは、インターフェイスごとに
サブネット番号を指定します：

```sh
sudo sixup -wan eth0 -lan eth1:0 -lan eth2:1
```

注意：/64 が一つでは LAN セグメント一つ分にしかなりません。委任のない回線では、サブ
ネット番号 0 のセグメントがそのプレフィックスを受け取り、残りには割り当てられません。
セグメント同士で通信する必要があれば `-lan-ula auto` で ULA を配布してください。

注意：MAP-E 回線では、送信元ポートが回線に割り当てられたポートセットの内側に収まって
いなければ、戻りの通信が届きません。この nftables ルールは sixup が維持します。書き込む
のは `inet sixup` テーブルだけで、終了時に自動で削除します。自分で書く場合は `-tunnel-nat off`
を指定してください。

## オプション

`sixup -h` は全オプションを以下のグループで一覧表示します。

- 真偽値のオプションは `=false` で無効にします。例：`-wan-ra=false`。
- 時間は Go の書式で指定します：`30s`、`10m`、`1h30m`。
- 繰り返し指定できるオプションは、値ごとに一回ずつ書きます：`-lan eth1 -lan eth2`。

### インターフェイスとプレフィックス

| オプション | 既定値 | 説明 |
|---|---|---|
| `-wan` | | WAN インターフェイス。必須。 |
| `-lan` | | LAN インターフェイス。繰り返し指定でき、書式は `名前[:サブネット番号]`。サブネット番号は 10 進数で、委任プレフィックスのうちどの /64 をこのインターフェイスに割り当てるかを決めます。省略すると、書いた順に 0、1、2 となります。LAN インターフェイスが複数あるときは委任プレフィックスが必要です。 |
| `-lan-ula` | | グローバルプレフィックスと並べて広告する ULA プレフィックス。`auto` はランダムな /48 を生成して状態ディレクトリに保存し、`fd12:3456:789a::/48` のようなプレフィックスはそのまま使います。複数はカンマ区切り。 |
| `-lan-iid` | | 各 LAN プレフィックス上のルーター自身のアドレスのインターフェイス識別子。カンマ区切りで一項目につき一アドレス、書式は `-wan-iid` と同じ。空なら RFC 7217 の安定アドレスを一つ。 |
| `-lan-deprecate-hold` | `10m` | 取り下げたプレフィックスを優先寿命 0 で広告し続ける時間。クライアントはその間に使用をやめます。 |

### WAN 側：DHCPv6 クライアント

| オプション | 既定値 | 説明 |
|---|---|---|
| `-dhcp6c-mode` | `auto` | `auto` は上流 RA の M、O フラグに従い、`on` は常にクライアントを動かし、`off` は動かしません。 |
| `-dhcp6c-pd-len` | `56` | 委任プレフィックス（IA_PD）を要求するときに示すプレフィックス長。`0` なら要求しません。 |
| `-dhcp6c-ia-na` | `true` | WAN インターフェイス自身のアドレス（IA_NA）も要求します。 |
| `-dhcp6c-pd-grace` | `10s` | 起動後に委任プレフィックスを待つ時間。その間 RA のプレフィックスは WAN 側にだけ使い、LAN には渡さないので、後から取り下げる必要がありません。 |
| `-dhcp6c-release` | `false` | 終了時に RELEASE を送り、プレフィックスとアドレスを返却します。既定では無効です。DUID を保存しているので、再起動後も同じプレフィックスを更新できます。ドライランでは常に返却します。 |

### WAN 側：上流 RA とアドレス

| オプション | 既定値 | 説明 |
|---|---|---|
| `-wan-ra` | `true` | 上流の RA を二つ目のプレフィックス取得元として受信し、それに基づいてデフォルトルートを維持します。 |
| `-wan-slaac` | `true` | A フラグ付きの RA プレフィックスについて、WAN インターフェイスに SLAAC アドレスを設定します。 |
| `-wan-iid` | | WAN インターフェイスの静的 SLAAC アドレスのインターフェイス識別子。カンマ区切りで一項目につき一アドレス。各項目は、RFC 7217 の安定アドレスなら `stable` または空、MAC アドレスから作るなら `eui64`、固定するなら `::1` や `::1111:2222:3333:4444` のようなサフィックス。最初のものを WAN アドレスとして報告します。 |
| `-wan-tempaddr` | `false` | WAN インターフェイスでも一時アドレスをローテーションします。設定は `-tempaddr-*` に従います。 |
| `-wan-prefer` | `pd` | 委任プレフィックスと RA プレフィックスの両方があるとき、どちらを使うか：`pd` または `ra`。 |
| `-wan-shared64` | `lan` | 上流から /64 が一つしか得られないときの配置。`lan`：/64 を LAN に置き、WAN リンク上のホストには /128 ルートを使います（RFC 7278）。`wan`：/64 を WAN 側に残し、LAN のホストごとに /128 ルートを使います。`split`：両側とも /128 ルートで、ルーター自身はまだ学習していないホストに届きません。/128 ルートは NDP 代理応答がホストを見つけたときに自動で追加します。 |

### LAN 側：RA の広告

| オプション | 既定値 | 説明 |
|---|---|---|
| `-ra-min` | `3m20s` | 定期 RA の最小送信間隔（MinRtrAdvInterval）。 |
| `-ra-max` | `10m` | 定期 RA の最大送信間隔（MaxRtrAdvInterval）。 |
| `-ra-lifetime` | `30m` | RA に載せるルーター寿命。 |
| `-ra-mtu` | `0` | RA で広告する MTU。`0` のときは、WAN 経路の MTU が LAN インターフェイスの MTU より小さければそれを広告します。WAN 経路の MTU は上流 RA または WAN インターフェイスから取ります。これで PPPoE の 1492 なども経路 MTU 探索に頼らずに済みます。 |
| `-ra-dns` | | 上流の DNS の代わりに広告する DNS サーバー。カンマ区切り。DHCPv6 サーバーもこれを使います。 |
| `-ra-pref64` | | 広告する NAT64 プレフィックス（RFC 8781）。例：`64:ff9b::/96`。空なら上流 RA の値をそのまま渡します。長さは 32、40、48、56、64、96 のいずれか。 |
| `-ra-route` | | ルート情報オプション（Route Information）として広告するプレフィックス。繰り返し指定可。 |

### LAN 側：DHCPv6 サーバー

| オプション | 既定値 | 説明 |
|---|---|---|
| `-dhcp6s-mode` | `off` | `stateless` は DNS などのオプションだけを返し、`stateful` はアドレスも割り当て、`off` はサーバーを動かしません。RA のフラグもこれに合わせます。 |
| `-dhcp6s-pool` | `1000-ffff` | 割り当てに使うインターフェイス識別子の範囲。16 進数で、下位 64 ビットを指します。 |
| `-dhcp6s-static` | | 固定割り当て。繰り返し指定可：`mac=<MAC>,addr=::100` または `duid=<16 進数>,addr=2001:db8::5`。 |
| `-dhcp6s-lease-preferred` | `1h` | 割り当てたアドレスの優先寿命。 |
| `-dhcp6s-lease-valid` | `2h` | 割り当てたアドレスの有効寿命。 |

### NDP 代理応答

| オプション | 既定値 | 説明 |
|---|---|---|
| `-ndproxy-mode` | `auto` | `auto` はプレフィックスが /64 のとき `forward` を有効にし、それ以外では無効にします。`forward` は応答する前に反対側を探索し、これを双方向に行うので、WAN リンク上のホストと LAN のホストの間でも通信できます。`prefix` は LAN プレフィックス内のアドレスに対する WAN 側からの要請に、探索せずにすべて応答します。`static` は `-ndproxy-static` の項目をカーネルの代理応答テーブルに登録するだけです。`off` は代理応答を無効にします。 |
| `-ndproxy-static` | | `static` モードで代理応答するアドレスまたはプレフィックス。繰り返し指定可。 |
| `-ndproxy-exclude` | | 代理応答しないプレフィックス。繰り返し指定可。 |
| `-ndproxy-ttl` | `30s` | 学習した代理応答エントリの存続時間。 |

### 自身のアドレスのローテーション

このグループは LAN 上のルーター自身のアドレスを制御します。`-wan-tempaddr` を付けると WAN 側も対象になります。

| オプション | 既定値 | 説明 |
|---|---|---|
| `-tempaddr-mode` | `off` | `temporary` と `both` は静的アドレスに加えてローテーションする一時アドレス（RFC 8981）を置き、`off` と `stable` は静的アドレスだけにします。 |
| `-tempaddr-regen` | `1h` | 新しい一時アドレスを作る間隔。 |
| `-tempaddr-preferred` | `1h` | 一時アドレスの優先寿命。 |
| `-tempaddr-valid` | `24h` | 一時アドレスの有効寿命の上限。使用中のアドレスはこの上限まで残し、使われなくなったものは早めに削除します。 |
| `-tempaddr-max` | `8` | 同時に持つ一時アドレスの上限数。 |
| `-tempaddr-desync` | `10m` | ローテーションごとに加えるランダムなずれの上限。 |
| `-tempaddr-skip-dad` | `false` | 重複アドレス検出を省略します。衝突がないと分かっているリンクでだけ使ってください。 |
| `-tempaddr-drain-grace` | `5s` | アドレスが使われなくなったと判断するための二回の確認の間隔。 |

### トンネル

| オプション | 既定値 | 説明 |
|---|---|---|
| `-tunnel-dev` | `sixup-ipv4` | IPv4-in-IPv6 トンネルデバイスの名前。トンネルのパラメータが揃うと、sixup がこのデバイスを作成または更新し、有効にして IPv4 アドレスを設定します。空ならデバイスを作りません。 |
| `-tunnel-mtu` | `0` | トンネルデバイスの MTU。`0` は WAN インターフェイスの MTU から 40 を引いた値です。 |
| `-tunnel-route4-metric` | `4096` | トンネル経由の IPv4 デフォルトルートのメトリック。わざと大きくしてあり、既存の IPv4 デフォルトルートが優先され、それがないときだけトンネルが引き継ぎます。`0` ならルートを追加しません。 |
| `-tunnel-nat` | `auto` | トンネルから出る通信のために nftables のテーブル `inet sixup` を維持します。`auto` は、MAP-E では必須のポート制限付き送信元 NAT（RFC 7597）を、専用の IPv4 アドレスを持つ回線では通常の送信元 NAT を設定し、事業者側で変換する DS-Lite では設定しません。いずれの場合も TCP MSS をトンネル MTU に合わせて制限します。`off` はルールを書きません。テーブルの外には一切触れず、終了時にテーブルを削除します。 |
| `-tunnel-mape-rules` | `true` | DHCPv6 に MAP-E オプションがないとき、日本の IPoE 事業者（v6プラス、BIGLOBE、OCN、NURO）のルール表を使い、委任プレフィックスから MAP-E のパラメータを求めます。 |
| `-tunnel-capture` | `true` | DHCPv6 にトンネルのオプションがないとき、トンネルの通信をキャプチャしてパラメータを特定します。`-dhcp6c-mode` が `off` でないことが必要で、ドライランでは行いません。 |
| `-tunnel-capture-max` | `2m` | キャプチャで待つ時間。最初のトンネルパケットで終わり、届かなければ諦めて、プレフィックスかアドレスが変わったときに再試行します。 |

### NAT64

| オプション | 既定値 | 説明 |
|---|---|---|
| `-nat64` | `off` | `jool` は [Jool](https://jool.mx) カーネルモジュール（4.1 以降、`modprobe jool` で読み込み）で NAT64 を設定します。`64:ff9b::/96` を変換するインスタンスを作って RA で広告し、変換結果は上記の送信元 NAT を通します。これで MAP-E 回線のポートを割り当てるのは一か所だけになります。`off` は設定しません。DNS64 は含まれず、お好みのリゾルバーに任せます。 |
| `-jool-instance` | `sixup` | sixup が作成、削除する Jool インスタンスの名前。 |
| `-jool-port-ranges` | `3` | MAP-E 回線のポート範囲のうち変換器に渡す数。残りは netfilter が使い、両者が同じポートを割り当てることはありません。回線がアドレスの全ポートを持つ場合は無視します。 |

### 実行

| オプション | 既定値 | 説明 |
|---|---|---|
| `-state-dir` | `/var/lib/sixup` | DUID、安定アドレスの元になる秘密値、ULA、リースを保存するディレクトリ。再起動をまたいで残してください。消えると事業者が別のプレフィックスを割り当てることがあります。 |
| `-no-sysctl` | `false` | `forwarding`、`accept_ra` などの sysctl を自動で設定しません。他の方法で管理している環境向けです。 |
| `-settle` | `1s` | パラメータがこの時間変わらなければ適用します。起動時に RA、委任プレフィックス、DNS、キャプチャの結果が順に届くので、まとめて適用するためです。取り下げはすぐに適用します。 |
| `-dry-run` | `false` | パラメータの取得、更新、トンネルの特定を一通り行い、経過を表示しますが、システムは変更せず、LAN に RA も送りません。 |
| `-dry-run-timeout` | `0` | ドライランを続ける時間。`0` は中断されるまで続けます。 |
| `-log-level` | `info` | 表示する最低レベル：`debug`、`info`、`warn`、`error`。 |
| `-v` | `false` | `-log-level debug` と同じ。 |
| `-version` | | バージョンを表示して終了します。 |
| `-license` | | sixup と、その派生元の作品のライセンスを表示して終了します。 |
